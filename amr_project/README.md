# AMR Project – Autonomous Mobile Robot Navigation, Localisation and Exploration

This repository contains our implementation of the Autonomous Mobile Robotics (AMR) project using ROS 2 Humble and the Robile mobile robot platform.

The project combines three major autonomous robotics functionalities:

1. Global and local path planning
2. Monte Carlo localisation
3. Autonomous frontier-based exploration with SLAM

The complete system was developed and tested in the Robile Gazebo simulation environment.

---

## Project Overview

The objective of the project is to build an autonomous navigation system capable of:

- navigating toward global goals,
- avoiding obstacles using LiDAR,
- planning collision-free paths using A*,
- estimating the robot pose using a particle filter,
- building an environment map using SLAM,
- detecting unexplored regions,
- automatically selecting exploration goals,
- and navigating toward those goals autonomously.

The project is implemented as a ROS 2 package called:

```text
amr_project
```

# 1. Path and Motion Planning

The first part of the project implements global and local navigation.

The navigation system combines:

- A* global path planning
- obstacle inflation
- waypoint following
- potential-field local navigation
- LiDAR-based obstacle avoidance

## A* Global Planner

The A* planner searches the occupancy grid and generates a collision-free global path from the current robot position to the requested goal.

The implementation supports 8-connected movement:

```text
↖  ↑  ↗
←  X  →
↙  ↓  ↘
```

Diagonal movement has a cost of `sqrt(2)`, while horizontal and vertical movements have a cost of `1`.

Diagonal corner cutting is prevented to avoid generating paths through obstacle corners.

Before A* planning, obstacles in the occupancy grid are inflated according to the robot safety radius.

Unknown cells are considered non-traversable during global planning.

Main implementation:

```text
amr_project/planning/astar.py
```

---

## Waypoint Following

The path generated by A* is converted from occupancy-grid coordinates into world coordinates.

The resulting path is represented as a sequence of waypoints.

To avoid making the robot follow every individual occupancy-grid cell, the path is reduced to provide a larger look-ahead distance between waypoints.

Main implementation:

```text
amr_project/planning/waypoint_follower.py
```

---

## Potential Field Local Planner

The local navigation system uses an artificial potential field.

An attractive force pulls the robot toward the current waypoint:

```text
Robot ----------------------> Waypoint
              Attractive Force
```

LiDAR measurements generate repulsive forces around nearby obstacles:

```text
Obstacle
   █
   █  -----> Repulsive Force
   █

                    Robot
```

The final navigation direction is obtained from the combination of attractive and repulsive forces.

The controller converts this direction into linear and angular velocity commands published on:

```text
/cmd_vel
```

Main implementation:

```text
amr_project/planning/potential_field.py
```

---

## Corridor Navigation Improvement

During testing, the original potential-field implementation could become trapped at narrow corridor entrances.

The repulsive forces generated by both corridor walls could dominate the attractive force and create a local minimum.

Several improvements were introduced:

- reduced obstacle influence distance,
- reduced excessive repulsive force,
- limited individual LiDAR repulsive contributions,
- limited total repulsive force,
- ignored obstacles behind the robot,
- reduced the effect of side walls on backward motion,
- increased waypoint look-ahead by reducing unnecessary intermediate waypoints.

These modifications allowed the robot to successfully navigate through narrow corridor sections and reach the global goal.

# 2. Localisation

The second part of the project implements Monte Carlo Localisation using our own particle filter.

Main components:

```text
particle.py
particle_filter.py
localization_node.py
```

The particle filter represents the possible robot pose using a collection of particles.

Each particle contains a possible robot state:

```text
(x, y, theta)
```

The localisation process follows the standard particle-filter cycle:

```text
Initialise particles
        |
        v
Motion update
        |
        v
Sensor update
        |
        v
Particle weighting
        |
        v
Resampling
        |
        v
Pose estimation
        |
        +-------> repeat
```

Odometry is used for the motion update while LiDAR measurements and the occupancy map are used to evaluate the particles.

The estimated robot pose is obtained from the particle distribution.

This implementation was tested in the Robile simulation while the robot was moving through the environment.

# 3. Autonomous Environment Exploration

The final part of the project combines autonomous exploration with SLAM.

SLAM Toolbox is used to construct the occupancy map online.

The exploration system analyses the generated map and detects frontiers.

A frontier is a boundary between:

```text
Known free space | Unknown space
                 ^
              Frontier
```

Main exploration implementations:

```text
amr_project/exploration/frontier_explorer.py
amr_project/exploration/exploration_node.py
```

---

## Frontier Detection

The exploration algorithm searches the occupancy grid for free cells that are adjacent to unknown cells.

Neighboring frontier cells are grouped into frontier clusters.

Small frontier clusters are rejected.

The center of each remaining cluster is converted from grid coordinates into world coordinates.

---

## Frontier Selection

Candidate frontier clusters are scored using their distance from the robot together with the size of the frontier.

The general scoring strategy is:

```text
score = distance_to_frontier - frontier_size_bonus
```

This encourages the robot to select useful frontier regions while considering navigation distance.

The selected position is published as:

```text
/exploration_goal
```

---

## Autonomous Exploration Pipeline

The complete exploration pipeline is:

```text
Robile
   |
   | /scan + TF
   v
SLAM Toolbox
   |
   v
/map
   |
   v
Frontier Detection
   |
   v
Frontier Clustering
   |
   v
Frontier Selection
   |
   v
/exploration_goal
   |
   v
A* Global Planner
   |
   v
Waypoint Follower
   |
   v
Potential Field Controller
   |
   v
/cmd_vel
   |
   v
Robot moves
   |
   v
New LiDAR measurements
   |
   v
SLAM expands the map
   |
   +------------------------> Repeat
```

During testing, the robot successfully reached a selected frontier goal. After reaching the goal and expanding the SLAM map, the exploration component automatically generated another frontier goal.

Example:

```text
[planner_node]: Goal reached.
[planner_node]: Map received: 296 x 215, resolution=0.050 m
[planner_node]: New goal received: x=1.42, y=-2.89, frame=map
```

This demonstrates the integration between mapping, frontier selection and autonomous navigation.


Clone this repository:

```bash

cd ~/ros2_ws

source install/setup.bash
```

# Running Autonomous Exploration

Start the exploration node:

```bash
ros2 run amr_project exploration_node
```

The node detects frontier regions and publishes goals to:

```text
/exploration_goal
```

Start the planner using the exploration goal topic:

```bash
ros2 run amr_project planner_node --ros-args \
-p goal_topic:=/exploration_goal
```

The robot should then:

1. detect a frontier,
2. generate an exploration goal,
3. calculate an A* path,
4. follow the path,
5. avoid nearby obstacles,
6. reach the frontier,
7. expand the map using SLAM,
8. select another frontier.

# Challenges and Improvements

Several practical problems were encountered while integrating the complete system.

## Coordinate Frames

Odometry coordinates and SLAM map coordinates cannot be assumed to be identical.

The planner was therefore modified to obtain the robot pose using the TF transformation:

```text
map -> base_link
```

This ensures that the robot pose, occupancy map, A* path and exploration goals use a consistent coordinate frame.

## Potential Field Local Minima

The potential-field controller could initially become stuck at corridor entrances.

Repulsive forces were limited and the controller was adjusted to improve navigation through narrow spaces.

## Dense A* Waypoints

Following every occupancy-grid cell caused unnecessary steering corrections.

The waypoint path was reduced to provide a larger look-ahead distance and smoother navigation.

## Dynamic SLAM Map

At the beginning of SLAM, the known map can be very small. As the robot moves and receives new LiDAR measurements, SLAM expands the map.

Planning and exploration therefore have to operate on a dynamically changing occupancy grid.

## Unreachable Frontiers

A detected frontier can occasionally be valid from the exploration perspective but unreachable in the inflated A* planning map.

In this situation A* correctly reports that no path is available.

A future improvement is to maintain a blacklist of unreachable frontier candidates and automatically select an alternative frontier.
